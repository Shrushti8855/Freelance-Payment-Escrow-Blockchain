# Freelance Payment Escrow Blockchain

A decentralized **freelance payment escrow platform** built with Solidity and Ethereum that securely holds client payments until predefined work milestones are completed and approved.

The platform introduces **smart-contract-based escrow, role-based access control, dispute resolution, refunds, and automated ETH settlement** without requiring a centralized intermediary.

## 🚀 Overview

Traditional freelance platforms typically rely on centralized intermediaries to hold payments, manage disputes, and release funds.

This project demonstrates how those core workflows can be implemented using a **blockchain smart contract**.

### Core workflow

```text
Client
  │
  │ Deposit ETH
  ▼
┌──────────────────────┐
│   Smart Contract     │
│      ESCROW          │
└──────────┬───────────┘
           │
           ▼
     Freelancer
           │
           │ Start Work
           ▼
     Submit Work
           │
           ▼
        Client
           │
           │ Approve
           ▼
   ┌─────────────────┐
   │ Payment Released│
   └─────────────────┘
```

If a disagreement occurs:

```text
Client / Freelancer
        │
        ▼
   Raise Dispute
        │
        ▼
   Smart Contract
        │
        ▼
    Arbitrator
      /     \
     /       \
Release      Refund
Freelancer   Client
```

## ✨ Features

### 💰 Smart Escrow

* Client deposits ETH directly into the smart contract.
* Funds remain locked inside the escrow contract.
* Payment cannot be released arbitrarily by the freelancer.
* Refunds return funds to the original client.

### 👨‍💻 Freelance Work Lifecycle

The contract manages the complete project lifecycle:

```text
FUNDED
   ↓
IN_PROGRESS
   ↓
SUBMITTED
   ↓
COMPLETED
```

### 🔐 Role-Based Access Control

Different actions are restricted according to the participant's role.

| Action          | Authorized Role     |
| --------------- | ------------------- |
| Create escrow   | Client              |
| Start work      | Freelancer          |
| Submit work     | Freelancer          |
| Approve payment | Client              |
| Cancel escrow   | Client              |
| Raise dispute   | Client / Freelancer |
| Resolve dispute | Arbitrator          |

Unauthorized users are rejected by the smart contract.

### ⚖️ Dispute Resolution

Both project participants can raise a dispute while the project is active.

The designated arbitrator can then decide between:

```text
Dispute
   ├── Release funds → Freelancer
   └── Refund funds  → Client
```

### 🔄 Cancellation & Refund

A client can cancel an escrow before work begins and receive the deposited ETH back.

### 🆔 Automatic Project IDs

Every escrow receives a unique project ID generated by the smart contract.

### 📡 Blockchain Events

The contract emits events for important operations including:

* Escrow creation
* Fund deposits
* Work started
* Work submitted
* Payment released
* Refund issued
* Dispute raised
* Dispute resolved

## 🛡️ Security

Security and authorization were treated as core parts of the project.

The automated test suite verifies:

* Unauthorized users cannot start work.
* Unauthorized users cannot release payments.
* Unauthorized users cannot raise disputes.
* Non-arbitrators cannot resolve disputes.
* Invalid freelancer addresses are rejected.
* A client cannot assign themselves as freelancer.
* Zero-value escrows are rejected.
* Payment cannot be released before work submission.
* Cancellation is rejected after work has started.
* Disputes cannot be resolved unless an escrow is actually disputed.
* Funds are cleared from escrow state before external ETH transfers.

The payment and refund functions follow a **Checks-Effects-Interactions-style flow**, reducing exposure to common reentrancy-related issues.

> This project is an educational/portfolio implementation and has not undergone a professional smart-contract security audit.

## 🧠 Smart Contract Design

The main contract is:

```text
contracts/FreelanceEscrow.sol
```

### Escrow states

```solidity
enum EscrowState {
    CREATED,
    FUNDED,
    IN_PROGRESS,
    SUBMITTED,
    COMPLETED,
    CANCELLED,
    DISPUTED,
    REFUNDED
}
```

### Escrow data

Each project stores:

* Project ID
* Client address
* Freelancer address
* Escrow amount
* Current project state
* Creation timestamp

## 🌐 Run the Local Blockchain

Start a local Hardhat blockchain:

```bash
npx hardhat node
```

Keep this terminal running.

In another terminal, deploy the contract:

```bash
npx hardhat ignition deploy ignition/modules/FreelanceEscrow.ts --network localhost
```

Or use the deployment script:

```bash
npx hardhat run scripts/deploy.ts --network localhost
```
